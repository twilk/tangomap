# AR Card Implementation Plan

> **For agentic workers:** steps are numbered; each ships independently. Build in order.

**Goal:** Let a dancer view their card as if held in the room — an immersive, motion-driven presentation on the web, cross-platform, with a true camera-AR path only where the device actually supports it.

**Reality check (why the steps are shaped this way):** "AR on the web" is not one thing. WebXR `immersive-ar` exists **only on Android Chrome**; iOS Safari has no WebXR AR and instead uses AR Quick Look, which needs a per-model `.usdz` file — impractical for a card generated per user. So a *true* camera-AR card is Android-only and asset-heavy. The shippable, cross-platform "AR card" is an **immersive, device-orientation-driven 3D presentation** (the card floats in your hand and parallaxes as you move the phone) — web-native, no assets, works everywhere the existing gyro tilt works. True WebXR is a later, capability-gated enhancement, not the foundation. AR is a documented MVP non-goal in `SPEC.md`, so this is a deliberate, incremental scope expansion.

**Tech Stack:** React 19 / TS, the card's existing CSS-var tilt plumbing (`--rx/--ry/--rxn/--ryn/--mx/--my` on `wrapRef`, `MAX_TILT`, `needsMotionOptIn`/`motionOn`), no new dependencies for steps 1–3.

---

## Steps

**1. Approach + feasibility decision (done in this doc).**
Ship "AR-lite" (immersive fullscreen 3D, orientation-driven) first; gate true WebXR behind `navigator.xr?.isSessionSupported('immersive-ar')` as step 4. No 3D-asset pipeline in steps 1–3. Reuse the card's existing tilt/motion path so there is one render path, not two.

**2. Immersive fullscreen card mode — the shippable core. ← built now.**
A "View in AR" action opens the card fullscreen on a dark scrim: enlarged, centred, the existing gyro/pointer tilt still driving it, a "move your phone to look around" hint, and a close control (button + Escape + scrim tap). Reuses `wrapRef`/`setTilt`; mirrors the existing `badge` fullscreen mode so there's no new motion code. Respects `prefers-reduced-motion` (static, just enlarged) and the iOS motion opt-in already in place. Locks body scroll while open. `aria`-labelled, focus moved to the close control, restored on exit.

**3. Motion permission + desktop polish.**
On iOS, the immersive mode surfaces the existing `requestPermission` opt-in inline ("Enable motion") instead of falling back to pointer silently. On desktop (no sensors) the mode is pointer-driven and shows a "drag to look" hint instead of "move your phone". Amplify `MAX_TILT` while immersive for a stronger in-hand feel, clamped so text stays readable.

**4. True WebXR (`immersive-ar`) where supported (optional, later).**
Feature-detected button, shown only when `isSessionSupported('immersive-ar')` resolves true (Android Chrome). Rasterise the card front to a texture and render it as a plane the user places in the room. Hidden everywhere else; never a broken button on iOS.

**5. Deep-link + telemetry.**
`/u/[handle]/card?ar=1` opens the immersive mode directly (shareable), and one lightweight event so we can tell whether the mode gets used before investing in step 4.
